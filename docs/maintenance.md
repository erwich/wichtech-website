# Maintain Wich Tech

This code-owned runbook complements NEST's `maintain-wich-tech` skill. Read `AGENTS.md`, `docs/north-star.md`, and `docs/architecture.md` first. Confirm the remote is `erwich/wichtech-website` and inspect the current branch, diff, package scripts, and workflow before editing or releasing. Paths below are relative to this repository.

## Content and design

- Articles: `src/features/writing/content/<article>/index.md`, with images beside the article. Read `collection.ts`, `query.ts`, and `publishing.mjs` for the actual publishing rules. Required metadata currently includes title, description, slug, date, and category; `draft: true` excludes unfinished posts. Future dates are filtered at build time, not automatically published by a scheduler. Inspect archive behavior before using `archived`; it is not a substitute for draft status.
- Preserve published slugs and image URLs where practical. Add permanent redirects for intentional URL changes. Check indexes, homepage cards, RSS, sitemap, and direct routes so drafts do not leak into production. A public preview is still public: never put confidential drafts or private screenshots in it.
- Projects: Markdown in `src/features/projects/content`, with schema and views in that feature. Keep the homepage summary consistent with the detail page. Public source links are optional; Revelation has private source.
- Homepage, About, and interests: `src/features/home` and `src/features/about`. Music descriptions and links: `src/features/music/recordings.ts`. Contact card/form: `src/features/contact`. Common chrome, metadata, prose, icons, theme, and settings: `src/shared`. Keep routes in `src/pages` thin.
- Read current site settings and metadata generation before revising titles or descriptions. Verify social preview image and Open Graph text as well as visible copy. Image changes should preserve originals, use neutral public filenames, and avoid oversized assets. Use the supported image-editing tool when retouching is requested.
- Check light/dark themes, mobile wrapping, keyboard focus, meaningful link labels, and readable captions for affected UI. Shared component changes need checks on their other consumers. Do not add tests that simply mirror copy.

## Contact and analytics

Web3Forms delivery lives in `src/features/contact/providers`. `PUBLIC_WEB3FORMS_KEY` is a public form identifier, configured through ignored local environment and the GitHub repository variable; do not embed the receiving email. hCaptcha must be enabled in the provider dashboard and integrated on the client. Preserve token validation, retry/error behavior, and initialization after Astro client navigation. A rendered checkbox is not proof of delivery. Send a test only within user authorization and have the inbox outcome confirmed; never silently solve a CAPTCHA.

GA4 lives in `src/features/analytics` and uses `PUBLIC_GA_MEASUREMENT_ID`. The intended account/property is WichTech / Wich Tech Website, not Eric's client properties. The approved implementation starts analytics by default, respects existing opt-outs, and offers footer preferences without an automatic popup. It has no regional detection. Preserve URL query/fragment sanitization and explicit page views after Astro navigation; keep enhanced measurement off to avoid duplicate page views and automatic form tracking. Do not transmit contact fields or enable ads features. These are recorded product choices, not a claim of legal compliance; changing policy or tracking scope is a separate decision. A loaded script does not prove a reporting event arrived, and a browser blocker can affect testing.

## Verification and publishing

Use the Node version selected by CI and `npm ci` when dependencies need installation. `npm run verify` performs type checks, build, and tests. Inspect rendered output for changed articles and UI; use a local preview or the separate Cloudflare preview when appropriate. Check actual Markdown links and image resolution, not just the source text.

Read `.github/workflows/site.yml` before release. Pull requests validate. A manual run with target `preview` builds with `SITE_PREVIEW=true` and deploys using `wrangler.preview.jsonc`; it has no production routes, contact delivery, or analytics and is excluded from indexing. Do not assume a PR automatically deploys a preview. Future-dated content will need a later build to become visible.

Production is triggered by a push to `master`, or the workflow's production dispatch on `master`, when `CLOUDFLARE_DEPLOY_ENABLED=true`. Pushing there is publishing; confirm the current request covers it. Use a branch/PR when review is requested or scope warrants it, attach any created PR to the task, and watch the relevant workflow through completion. Do not run a competing local deployment while CI is releasing. Keep dependency and infrastructure upgrades separate from copy changes unless needed to solve the task.

Deployment secrets are `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. The dedicated deployment token has account Workers Scripts Edit and wich.tech Workers Routes Edit permissions. Public Web3Forms and GA identifiers are repository variables. Check names/readiness without printing values; use secure stdin or the provider's credential store for authorized credential setup. Do not infer secret presence or validity from this document.

Cloudflare Workers Static Assets hosts production on the `wichtech-website` Worker, with custom domain `www.wich.tech`. The `wichtech-redirect` Worker owns the `wich.tech` custom domain and preserves path/query while redirecting to HTTPS www. The separate preview Worker uses its own route-free config. GitHub Actions is the sole automatic deployment owner; do not enable Workers Builds too. Wrangler configuration is authoritative for the desired bindings. Read `docs/launch.md` for account setup and recovery context.

After deployment, verify the intended page over HTTPS, assets, and relevant navigation. Routing changes additionally require apex redirect, deep path/query preservation, and real 404 checks. Domain bindings and CI were migrated on October 8, 2026; recheck current state rather than assuming it remains unchanged. The retired GitHub DNS targets and wildcard Worker routes were removed. GitHub Pages' custom-domain association was cleared, but disabling the legacy Pages site through the API was rejected. It may still exist at the GitHub address and is not the production origin. Do not claim it is disabled.

For a failed release, inspect the failing job and fix the cause before retrying. Preserve the last working deployment. Roll back the affected Worker to a verified prior deployment when authorized; follow with a source correction or revert so the next CI build cannot restore the fault. DNS and credential changes need separately bounded target, effects, verification, and recovery; never change email or unrelated zones as part of website maintenance.
